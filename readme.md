# ДЗ урока № 21 — Защита от DoS-атак, ограничение доступа

ДЗ будем делать используя WordPress в Docker из урока 14:

Набор файлов для запуска в каталоге `wp`.
В каталоге `etc` дополнительные файлы для размещения вместе с конфигами `fail2ban` хостовой системы.

Секреты определены через файл `.env`, который не опубликован в репозитории. Ожидаемое содержимое файла:
```
MYSQL_ROOT_PASSWORD=
MYSQL_USER=
MYSQL_PASSWORD=
```

Будем использовать доменное имя `otus-angie-14.s7h.ru`

1. Наиболее подверженным атаке видится _location_ динамического содержимого `~ \.php$` - обращения к нему приводят к исполнению php-кода, запросам в БД.
2. Для наших демонстрационных целей ограничим подключения к динамическому содержимому одним запросом в секунду: `rate=1r/s` в директиве `limit_req_zone`
3. настроим блокировку нарушителей средствами `fail2ban`:
    1. Установим `fail2ban` в хостовую систему:
    ```
    sudo apt install fail2ban
    ```
    2. В `docker-compose.yml` настроим запись логов angie в хостовую систему
    3. В `/etc/fail2ban/filter.d/angie-limit-req.local` пропишем regexp для поиска событий ограничения в логах angie
    4. В `/etc/fail2ban/jail.d/angie-limit-req.local` пропишем блокировку порта для цепочки Docker'а

    После перезапуска службы `fail2ban` делаю много запросов средствами powershell:
    ```powershell
    1..20 | % { Invoke-webRequest -UseBasicParsing -Uri "https://otus-angie-14.s7h.ru/sample-page/" } | % StatusCode
    ```
    Но после 10 перестаю получать ответы. А команда `fail2ban-client status angie-limit-req` показывает мой IP в списке `Banned IP list`
4. "админку" wordpress выделим в отдельный _location_ и разрешим только с IP-сети `76.78.152.0/21`
